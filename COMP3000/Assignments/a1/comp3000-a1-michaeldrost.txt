printf calls are translated into two different calls: __printf_chk() and puts().

__printf_chk() is used when printf() needs formatting. For example, the assembly for:

printf("Running %s\n", menu[choice]);

uses:

call    __printf_chk@PLT

because the string contains the %s format specifier.

The calls that only print a fixed string, such as:

printf("Command failed.\n");

are translated into:

call    puts@PLT

because there are no format specifiers and puts() can print the fixed string directly.

This can be seen in run_program(), where "Running %s\n" uses __printf_chk(), while "Command failed." and "Command succeeded." use puts().

run_program() can be modified to avoid system() by using fork(), execve(), and waitpid(). The child process can execute the selected program using execve(), while the parent waits for the child and checks its exit status.

One possible replacement for run_program() is:

void run_program(int choice)
{
        pid_t pid;
        int status;

        printf("Running %s\n", menu[choice]);

        pid = fork();

        if (pid == 0) {
                char *args[] = {menu[choice], NULL};
                char *envp[] = {NULL};

                execve(menu[choice], args, envp);
                exit(1);
        } else if (pid > 0) {
                waitpid(pid, &status, 0);

                if (WIFEXITED(status) && WEXITSTATUS(status) == 0) {
                        printf("Command succeeded.\n");
                } else {
                        printf("Command failed.\n");
                }
        } else {
                printf("Command failed.\n");
        }

        return;
}

This works because fork() creates a child process. The child calls execve() to replace itself with the selected program. If execve() fails, the child exits with a nonzero status. The parent uses waitpid() to wait for the child and then checks its exit status.

The commands in the original menu are absolute paths, such as /usr/bin/ls and /usr/bin/ps, so execve() can execute them directly without needing execvp(). The custom command also needs to be an executable path rather than a shell command containing options, because execve() does not perform shell parsing.
